# 笔记

[返回项目首页](../../README.md) · 默认地址：`/pwa-apps/notes/`

笔记保存在当前浏览器的 `localStorage`。底部导航可切换笔记与设置；设置页会显示本地是否有待同步修改和上次成功同步时间。配置完成后点击“立即同步”会直接访问 GitHub；编辑时不会自动上传。

## 配置 GitHub 访问

1. 创建私有仓库 `liuzhenghua/pwa-apps-data`。
2. 按[根 README 的通用步骤](../../README.md#云端数据与加密-token-配置)配置构建时加密 Token；也可在页面手动输入 Token。
3. 在设置页打开“同步配置”，填写名字、云端访问口令（构建时配置时）和数据加密口令，点击“保存并同步”。以后可直接在设置页点击“立即同步”。

手动输入模式下，名字、Token 和数据加密口令会保存在当前浏览器的 `localStorage`。构建时配置加密 Token 后，页面只要求云端访问口令；它保存在当前浏览器，不保存解密后的 Token。弹窗中的“清除已保存的配置”会删除本地配置。数据加密口令丢失后无法解密云端笔记。

笔记使用独立目录，每条笔记单独存一个加密文件。名字支持字母、数字、下划线和连字符；文件名是随机笔记 ID，不包含标题：

```text
pwa-apps-data/
└── notes/
    └── <名字>/
        ├── _crypto.json
        ├── <笔记ID-1>.json
        └── <笔记ID-2>.json
```

## 同步规则

应用保存上次成功同步时的本地笔记快照与云端文件 SHA 列表。每次同步先读 GitHub 目录：

- 两边都没有变化：直接结束，不下载或解密每条笔记。
- 仅一边有变化：自动向另一边同步。
- 两边都有变化：按笔记 ID 合并；同一笔记选择 `updated` 时间较新的版本。删除依据上次同步快照判断。
- 同一时间出现不同内容，或一边编辑而另一边删除：显示差异，让用户选择保留本地或云端，并在覆盖前确认。

更新时间取自设备时钟，因此各设备时间需要准确。发生变化时仍需读取云端笔记文件；GitHub Contents 目录接口接近 1000 个文件时，应用会停止同步。每条云端写入会单独提交；中途失败可能只完成部分写入，重新同步会再次比较状态。

## 云端加密原理

加密与解密在浏览器内通过 Web Crypto 完成。GitHub 收到的是加密配置和笔记密文，不是明文笔记或加密口令。

1. 每个名字首次上传时生成 16 字节随机 salt。口令与 salt 经 PBKDF2-HMAC-SHA-256（600,000 次迭代）派生出 256 位 AES 密钥。同一文件夹的笔记共用该密钥。
2. `_crypto.json` 保存版本、KDF 参数、salt，以及用该密钥加密的固定校验文本。`checkIv` 用于在下载笔记前检查口令，不包含口令或 AES 密钥。
3. 每次写入笔记都生成新的 12 字节随机 IV，用 AES-256-GCM 加密包含 ID、标题、正文和更新时间的 JSON。文件只保存 `version`、`iv` 和 `ciphertext`；GCM 认证标签包含在密文中。
4. 解密时先派生密钥并验证校验文本，再逐条解密笔记。salt 和 IV 不需要保密，但必须与密文一起保留。

云端仍可看见文件夹名字、随机笔记 ID、文件数量、大小和 Git 提交时间。当前浏览器中的明文笔记、Token 与口令保存在 `localStorage`；云端加密只保护 GitHub 仓库里的内容。

实现见 [crypto.ts](src/crypto.ts)、[sync.ts](src/sync.ts) 和 [main.tsx](src/main.tsx)。通用启动与部署步骤见[项目 README](../../README.md#本地启动)。
